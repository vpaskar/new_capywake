# CapyWake — new architecture and rebuild plan

Companion to `CAPYWAKE_LEGACY_AUDIT.md`. Written 2026-11-16, before any code.
Revised after the Phase 0 pre-review — see `docs/phases/PHASE_00_PRE_REVIEW.md`
for the critique this document already answers.

## 1. What we are building

A brand-new Flutter app in `new_capywake/`, whose UI is reconstructed from
`01_REFERENCES/screens/primary/` and whose alarm behavior reproduces the
semantics proven in `../capywake` (read-only).

The visual target is **1:1 as close as practical**, because that is the
explicit owner requirement. The measurement below makes "as practical"
falsifiable rather than a matter of opinion.

### The fidelity contract (two tiers)

The reference PNGs were generated by an image model and contain art that does
not exist in the asset package. Verified example, saved under
`docs/visual/_evidence/`: the Home hero shows a capybara in a **blue nightcap
holding a yellow duck, with an alarm clock on the nightstand**;
`today_integrated.png` — the supplied Today scene — has **no cap, no duck, and
a mug and books where the clock is**. They were generated separately. A literal
pixel diff can therefore never pass, and a plan implying otherwise would
produce either a false "done" or an endless loop.

So fidelity is split, and only one tier is a gate:

**Tier A — structural fidelity. Binding, measured, pass/fail.**
Layout geometry, block proportions, palette, type scale and weight, corner
radii, control shapes and all their states, and the *placement* of art must
match the reference within **±4 pt on major block positions at 393 × 852**.
This is what makes the app read as the mockup, and it is fully achievable.

**Tier B — illustration fidelity. Best-effort, declared, never silently
substituted.**
Where the mockup's art has no counterpart in the package, the nearest supplied
asset is used and the substitution is recorded in that screen's deviation log.
We do not generate new art and we never claim a substitute is the original.

Each UI phase opens with a written **asset-to-mockup mapping** for its screens,
so every substitution is known before the screen is built rather than
discovered after it.

### Measured target geometry

Every primary mockup is **851 × 1847 px**. At 2.165× that is **393 × 853 pt** —
iPhone 14 Pro, which is available as a simulator on this machine.

Screenshot comparison is therefore **exact**: the simulator capture and the
reference PNG are the same viewport, and a diff is meaningful. This is the
single biggest reason the rebuild can claim fidelity where the retrofit could
not.

Secondary verification sizes: **320 pt** (smallest supported width) and
**430 pt** (iPhone Pro Max). References are concept art; these two are checked
for "no overflow, nothing illegible", not for pixel match.

### Typography

The mockups use a rounded, heavy, geometric sans throughout — the wordmark, the
`7:00 AM` time, every heading. Flutter's default (Roboto / SF) is not that
face, and typography is one of the loudest fidelity signals: the wrong face
makes every screen read as a near-miss no matter how accurate the layout is.

Phase 01 selects one SIL OFL family (candidates: Nunito, Baloo 2, Quicksand,
Fredoka) by rendering "CapyWake 7:00" at the mockup's size in each and
comparing against a reference crop. The chosen family, its licence and the
comparison go in `docs/visual/typography/`.

The **wordmark itself is an asset**, not a font match — cropped from the
reference header. No supplied font reproduces its lettering, and it is the
owner's own generated art, so bundling it is clean.

## 2. Navigation — decided

```
AppShell  (bottom nav: Home · Alarms · Stats)
├── /home          Home / Today
├── /alarms        Alarms list
└── /stats         Stats  (segments: Sleep · Alarms · Games)

Pushed routes (no bottom nav):
  /alarms/new, /alarms/:id      Add / Edit alarm
  /settings                     from the gear in the header
  /settings/reliability         Reliability checklist
  /settings/walkthrough         Setup walkthrough
  /settings/sounds, /settings/puzzle
  /onboarding                   outside the shell
  /ringing                      outside the shell, full-screen
  /puzzle                       hosted by ringing
```

Three tabs. Settings always reachable via the gear, from all three tabs.
Rationale and the evidence table are in the audit, §6.

`/settings` is declared **outside** the `StatefulShellRoute` with the shell's
branch state preserved, so popping it returns to the tab it was pushed from. A
router test asserts push-from-each-tab → pop → same tab, for all three.

## 3. Layer architecture

Inherits the legacy's shape, because it is sound and tested.

```
lib/
  app/          bootstrap, router, theme wiring, AppShell
  core/         pure Dart domain. NO Flutter widgets.
                models/ schedule/ wake/ lifecycle/ engine/ puzzle/
                history/ permissions/ reliability/ sleep/ settings/
  data/         Drift DB, DAOs, repositories, platform adapters
  design/       design tokens + shared illustrated components
  features/     home/ alarms/ stats/ settings/ onboarding/ ringing/
                games/ reliability/
  l10n/         10 ARB files
```

Rules carried over verbatim:

- `core/` has no Flutter import. It is headless and fully testable.
- The platform alarm engine sits behind `core/engine/AlarmEngine`; only
  `data/` imports the `alarm` package.
- Clock times are **integer minutes since local midnight** in data/calc layers,
  formatted at the UI boundary via `intl`. Durations are integer minutes.
- Models carry no derived state — no cached "next fire time".
- `SleepGateway` has **no write method**. CapyWake reads sleep, never writes.

### `design/` — the new layer

This is what the legacy lacked and what makes the mockups reachable.

```
design/
  tokens.dart        CapyColors, CapySpacing, CapyRadius, CapyType, CapyDuration
  art.dart           typed catalogue: every bundled asset, by id
  scene_header.dart  SceneHeader — hero art + crop/alignment + content overlay
  capy_card.dart     the rounded cream card with hairline
  capy_button.dart   the chunky orange CTA with its darker lower edge
  capy_toggle.dart   the large green/grey switch from the mockups
  capy_nav_bar.dart  the three-tab illustrated bottom bar
  day_pills.dart     the Mon–Sun repeat pill row
  meadow_footer.dart the grass band above the nav
  segmented.dart     the Sleep/Alarms/Games segment control
```

**`SceneHeader` is the most important component in the app.** Every primary
screen opens with one. It owns: the hero image, a `BoxFit`/`Alignment` crop
chosen per scene so the capybara is never squashed or cut at the face, the
cream card that overlaps the art's lower edge, and the safe-area padding. One
component, five screens, so the compositions cannot drift apart.

## 4. Art pipeline

Owner decision 2026-11-16: **raster is the medium.** The legacy's
vector-capybara rule is not inherited; the audit §2 explains why.

### What gets bundled

| Source | Destination | Count | Notes |
|---|---|---|---|
| `02_ASSETS/header_scenes/*_integrated.png` | `assets/art/scenes/` | 4 | 1536×1024, the hero art. `upscaled_older/` and `alternate_*` are NOT bundled |
| `02_ASSETS/asset_library/mascots/` | `assets/art/mascots/` | 31 − 2 | `thinking.png` + `sleepy_eyes.png` replaced by `02_ASSETS/mascot_fixes/` versions |
| `02_ASSETS/clean_icons/` | `assets/art/icons/` | 11 | Preferred over `asset_library/icons/` (37 earlier, rougher cuts) |
| `02_ASSETS/asset_library/decor/` | `assets/art/decor/` | 14 | Grass, bushes, flowers, sun, signpost |
| `02_ASSETS/animations/*/loop.webp` | `assets/art/anim/` | 5 | Animated WebP only — **not** the 180 PNG frames |
| `../capywake/assets/sounds/*.wav` | `assets/sounds/` | 12 | Re-generated via the legacy's `tool/generate_tones.dart`, not copied blindly |

Explicitly **not** bundled: `SOURCE_ARCHIVES/`, `05_LEGACY_HANDOFFS/`,
`01_REFERENCES/` (reference only), `asset_library/scenes/` (14 older scenes
superseded by `header_scenes/`), `asset_library/ui/` (18 raster buttons/toggles
with baked-in English — these become real widgets).

### Import gate — every asset is audited before it ships

A `tool/audit_art.dart` run on import checks each file for: alpha channel
present, ghost pixels (alpha ≤ 16 scattered by automatic masking) cleared,
transparent margin trimmed, intrinsic size recorded, and a severed-crop
eyeball check. The legacy found two broken cuts this way; the manifest warns
there are more.

Budget: **measured in Phase 01, not guessed.** Four hero scenes alone are
~1.9 MB each as supplied; a number picked now would be either toothless or a
false blocker. Phase 01 (a) downscales each asset to 2× its largest on-screen
render box, (b) re-encodes to WebP — lossy `-q 82` for the photographic scenes,
lossless for flat-colour cutouts — and verifies visual parity at render size,
then (c) records the real total and sets `tool/check_bundle_size.dart` at
**measured + 20 % headroom**.

### Rules for art in widgets

- Art is **behind** content, never on top of a control.
- Text is always a real `Text`; buttons are always real widgets. No raster
  button with baked copy ever ships — it cannot localize into 10 languages.
- Scenes crop (`BoxFit.cover` + per-scene `Alignment`), never distort.
- `precacheImage` for the four hero scenes at startup.
- No animation on the ringing surface; `MediaQuery.disableAnimations` honored
  everywhere.

## 5. Tests and gates

Full legacy rigor, including all 10 locales (owner decision).

```
flutter pub get
flutter gen-l10n                                            # if ARB changed
dart run build_runner build --delete-conflicting-outputs    # if Drift changed
dart format --set-exit-if-changed .
flutter analyze                                             # zero issues
dart run tool/check_arb.dart                                # 10 locales complete
dart run tool/audit_art.dart                                # alpha/size/manifest
dart run tool/check_bundle_size.dart                        # art budget (set in Phase 01)
flutter test --coverage
dart run tool/check_coverage.dart                           # project >= 85%
dart run tool/check_coverage.dart --min 95 --path lib/core  # core >= 95%
```

Locales: `en de ru es tr fr it pt ar ja`. Arabic is RTL — direction-aware
widgets only (`EdgeInsetsDirectional`, `start`/`end`), never hardcoded
`left`/`right`.

### Visual verification — the part that actually decides fidelity

The legacy repo captured **zero** screenshots across 40 phases because its
runner had no display. If the capture mechanism is not built and proven before
the first screen, every later phase will claim a verification it did not
perform — which the master prompt forbids outright.

So the harness is a **Phase 01 deliverable with its own definition of done**,
proven on the empty shell before any real screen exists:

| Piece | Does |
|---|---|
| `integration_test/capture_test.dart` | Drives the app, writes PNGs via `IntegrationTestWidgetsFlutterBinding.takeScreenshot` |
| `tool/capture.sh <screen>` | Boots the iPhone 14 Pro simulator, runs the capture, writes `docs/visual/<screen>/actual.png` |
| `tool/compare.dart` | Writes `side_by_side.png`, prints per-block position deltas in pt |

Phase 01 is not done until `tool/capture.sh` has produced a real PNG of the
shell at 393 × 852. If it cannot be made to work, that is a blocker raised in
Phase 01 — not a surprise in Phase 03.

Then, per UI phase, per screen:

1. Capture at 393 × 852.
2. `docs/visual/<screen>/` gets the reference, the capture, the side-by-side.
3. Score the `06_VISUAL_QA_AND_ACCEPTANCE.md` scorecard: composition,
   proportions, typography, palette, capybara integration, control states,
   a11y, small/large device.
4. Tier A deltas over ±4 pt are **defects**, fixed in that phase.
5. Tier B substitutions are **listed by name** with the asset used.
6. Every remaining deviation is *fixed*, *accepted with rationale*, or
   *blocked*. No percentage claim without a stated method.

A screen is not done because it functions. It is done when the comparison is
recorded and its deviations are named.

## 6. Content integrity — three screens that will try to lie

The mockups show data the app does not have. Each of these is a place where
the natural implementation violates a hard rule of the handoff, so each gets a
mechanism rather than an intention.

### Stats — no fabricated numbers

`05_STATS.png` shows `7 h 32 m`, `+18 min vs. last week`, seven bar values,
`6 days`, `Best: 14 days`, `Goal 8 h`, `Avg. 94 %`, `10:28 PM`, `52 h 44 m`.
Building the screen to *look* right is building a screen full of those numbers,
and the owner chose all three segments, which triples the surface.

1. **The empty state is the default, not the fallback.** Every Stats widget
   renders no-data first; populated is the branch. A widget test asserts the
   empty state renders against an empty repository.
2. **`tool/check_no_fake_stats.dart`** greps `lib/features/stats/` for numeric
   literals in user-facing positions and fails the build. It lands in the same
   phase as the screen.
3. **Demo data lives in tests and goldens only**, never in `lib/`. The
   side-by-side capture may run against a seeded test repository, and the
   capture record states that it did.

`Goal` and `Avg. %` appear only once the user has set a goal *and* Health has
supplied enough nights. No invented percentage ships.

### Settings — the Account group cannot exist

`04_SETTINGS.png` shows Backup & Sync "On (iCloud)", Restore Purchases, and
About. The product has no backend and all alarm features ship in the paid
download, so two of those three rows would be fiction. Decided now rather than
improvised in phase 07:

- **Backup & Sync — dropped.** It implies a backend that is an explicit
  non-goal.
- **Restore Purchases — dropped.** Nothing to restore. If IAP is ever added,
  the row returns with it.
- **About CapyWake — kept**, real version from `package_info`.
- The group is renamed **About** and gains the two rows the product contract
  requires and the mockup lacks: **Reliability Checklist** and **Setup
  Walkthrough**.

The group keeps the mockup's exact visual treatment. Logged as an intentional
Tier B deviation with this reasoning.

### Home — four game cards, zero games, for roughly ten phases

Home ships in phase 03; the first game lands around phase 11. `01_HOME.png`
shows Step Quest, Shake DJ, Catch the Capy and Find the Impostor.

`core/games/game_catalogue.dart` is typed, with
`GameAvailability { playable, comingSoon, blocked }` per entry. Home renders
the rail from the catalogue. A `comingSoon` card is visibly and semantically
marked and opens a short "not built yet" sheet — never a dead tap or a broken
route. The rail is tested with **zero** playable games, which is the state it
ships in.

Two entries are `blocked` from day one, each carrying its reason:

- **Step Quest** needs step counting. `sensors_plus` was chosen specifically to
  avoid `ACTIVITY_RECOGNITION` (Android 10+) and Motion & Fitness (iOS).
- **QR Treasure Hunt** needs a camera dependency that does not exist.

Both add a store-visible permission, so each needs an explicit owner decision
to unblock, and both are sequenced last. Step Quest is the **first card on the
Home mockup**, so this is visible on a primary screen — logged as a deviation
caused by a real platform constraint, not an oversight.

## 7. Phase plan

Each phase: plan → **adversarial pre-review** → revised plan → implement →
validate → **2 self-reviews + 1 full-project review** → post-review →
tracker/memory/handoff update → commit. The handoff mandates the pre-review;
the legacy mandates the post-reviews; we do both.

**20 phases, 00–19.** `ai-orchestration/PHASE_TRACKER.md` is canonical for
sequencing; this table is a summary and must be updated with it.

| # | Name | Delivers |
|---|---|---|
| 00 | Discovery and source of truth | Audit, plan, pre-review, self-review, reuse audit, tracker, repo skeleton |
| 01 | Foundation | Flutter project, 10-locale ARB, tokens from the sampled palette, font selection, `design/` components, router + shell, art import/audit/encode tooling, **working capture harness** |
| 02 | Domain + persistence | **Port** `core/` + `test/core/` + ARB + Drift tables from `../capywake`; adapt, re-gate at ≥95% core |

The five mockup screens are complete by phase 08.

**The domain precedes the first screen, deliberately.** Home exists to show the
next-alarm card; building it before `Alarm` exists would mean a throwaway
view-model and then a rewrite in phase 04 — which is exactly the
retrofit-an-existing-screen motion that failed last time. Home is built against
the real model and a repository backed by an in-memory Drift database, so no
screen is ever rewritten to meet the domain.

## 8. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Mockup art has no counterpart in the package | High | Two-tier fidelity contract (§1); per-screen asset mapping written before the screen is built; substitutions logged by name |
| The capture harness never works, so fidelity is claimed but unverified | High | Harness is a Phase 01 deliverable with its own DoD, proven on the empty shell before any screen |
| Mockup Stats numbers get hardcoded | High | Empty state is the default and is tested; `check_no_fake_stats.dart` gate; demo data confined to tests |
| Alarm regression vs legacy semantics | High | Legacy edge cases (final alarm, stale re-arm, dismiss-once, iOS 64-cap) become named tests in phases 02 and 05 |
| Hero scene crops badly at 320 pt or 430 pt | High | `SceneHeader` owns per-scene `Alignment`; checked at 3 widths every UI phase |
| Raster art bloats the bundle | High | Downscale to 2× render box, WebP, gate set at measured + 20 % in Phase 01 |
| Supplied cutouts have alpha artifacts | Medium | `audit_art.dart` on import; 2 known-broken files already replaced from `mascot_fixes/` |
| Raster art cannot re-tint for dark mode | Medium | Dark = scrim + surface swap, decided per screen alongside light in Phase 01 |
| 10 locales slow UI iteration | Medium | English written first *within* a phase; the other 9 before that phase's commit, so the ARB gate never goes red at a phase boundary |
| Dead game cards on Home for ~10 phases | Medium | Typed catalogue with `playable`/`comingSoon`/`blocked`; rail tested with zero playable games |
| Two games blocked by a permission decision | Medium | Marked `blocked` from day one with reasons; sequenced last; each needs an explicit owner decision |
| Wrong typeface undermines every screen | Medium | Font chosen in Phase 01 by comparison against a reference crop; wordmark bundled as art |
| Android unverified on this machine | Medium | Explicit open item; never marked tested until a device or emulator actually runs it |

## 9. Explicit non-goals

No auth, no cloud sync, no backend, no social or leaderboard features, no fake
analytics. No sleep-stage detection or sleep *measurement* — CapyWake reads
what the user's own wearable already recorded, or shows nothing. No claim of
being more reliable than the OS clock app.

**No copied view code from `../capywake`** — no screens, no widgets, no theme,
no router, no `CustomPaint` cast. The domain beneath is a different matter: see
§10.

## 10. What is ported from `../capywake`

Revised 2026-11-16 (self-review SR-1). Phase 00 originally banned *all* reuse,
which was a mistake — it conflated "never modify the legacy" with "never take
anything from it". The master prompt's actual instruction is *"Do not copy the
previous UI implementation or layouts"* and *"Preserve the product's
capabilities, not its old view tree."* A pure-Dart schedule engine is a
capability.

**The rule, stated so it cannot be misread: if a file imports Flutter, it is
not ported.** The sole exception is `lib/core/theme.dart`, which imports
Flutter *and* is not ported.

| Ported | Size | Verified |
|---|---|---|
| `lib/core/` minus `theme.dart` | 62 files, 9,825 lines | Only `theme.dart` imports Flutter, and nothing in `core/` depends on it |
| `test/core/` | 48 files, 15,503 lines | **932 tests pass**; 0 of 48 import feature code |
| `lib/l10n/` | 383 keys × 10 locales | Only 3 keys navigation-coupled |
| `lib/data/` | 12 files, 2,500 lines | Tables and mappers only — **start at `schemaVersion = 1`**, drop the 6-version migration history (greenfield, no users) |
| `tool/`, `assets/sounds/` | — | `check_arb`, `check_coverage`, `generate_tones` + 12 WAVs with clean licences |

| Not ported | Size |
|---|---|
| `lib/features/`, `test/features/` | 82 files, 26,710 lines |
| `lib/features/common/capy/` | 1,939 lines of `CustomPaint` |
| `lib/core/theme.dart` | 704 lines |
| `lib/app/shell.dart`, `router.dart` | 590 lines |

Full file-level verdicts in `CAPYWAKE_REUSE_AUDIT.md`.

This is not the retrofit that failed. That failed in the **view layer**, for a
documented reason — a rule requiring the capybara be vector `CustomPaint`.
Nothing in `lib/core/` has an opinion about how a capybara is drawn.

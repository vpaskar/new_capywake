# Art request — what to generate

For the owner. Derived from `asset_gaps.md`; that file has the evidence and the
measurements. This one is just the shopping list.

Everything here is **raster PNG with transparency** unless the row says
otherwise, in the same storybook style as the existing package.

**Drop new files in `reference/02_ASSETS/`** (the directory the phase plan reads
from) — not into `assets/`, which Phase 01's pipeline generates. Keep the
filenames below so nothing has to be rewired.

Priority 1 is the only one that blocks a phase. 2–4 are quality; the app ships
without them, visibly below the mockup.

---

## 1. Four game tiles — **BLOCKING Phase 03**

The only item that stops a phase reaching its fidelity bar.

`01_HOME.png` shows a rail of four tiles, each a **complete illustration**:
a capybara **on a painted background**, inside a rounded square. The package has
only transparent cutouts with no backgrounds, so there is nothing to crop from.

Put them in `reference/02_ASSETS/game_tiles/`:

| File | Must show | Nearest existing (and why it fails) |
|---|---|---|
| `step_quest.png` | Walking, **blue backpack**, **white headband**, green park background, small motion marks | `walking_backpack.png` — no headband, no motion marks, no background |
| `shake_dj.png` | **Pink** headphones, **purple** stage background, floating music notes | `music_headphones.png` — headphones are **grey**, no background |
| `catch_the_capy.png` | **Mid-leap**, green meadow, speed lines | `athletic.png` — capybara is **sitting**, no background |
| `find_the_impostor.png` | Detective hat, magnifier, warm cream background | `detective.png` — good pose, still needs the background |

**Specs**

- **Square, ≥ 360×360 px.** The tile renders at ~120 pt, so 360 is the 3×
  minimum; 512² is better and leaves headroom.
- **Background included and opaque** — this is the whole point. The painted
  scene is part of the tile.
- Capybara fills most of the frame, as in the mockup.
- Leave ~8% padding inside the square; the app rounds the corners itself.
- **No text in the image.** Labels ("Step Quest", "Shake DJ") are real `Text`
  widgets — they have to translate into 10 languages.

Crop of what the mockup shows:
`docs/visual/_evidence/asset_gaps/mockup_game_rail.png`

## 3. Mascots at a usable resolution

All 31 are **114–343 px**, most around 160. At 3× that is sharp to ~53 pt.
Anything bigger is upscaled, and upscaling soft-edged illustration reads as
blur.

| Use | Render box | Needs @3× | Have |
|---|---|---|---|
| Game tile | ~120 pt | 360 px | 114–274 ✗ |
| Empty state | ~96 pt | 288 px | 114–274 ✗ |
| List row | ~44 pt | 132 px | ✓ |
| Footer decor | ~32 pt | 96 px | ✓ |

**Same artwork, re-rendered at ≥ 512×512**, same filenames, transparent
background. If a larger original exists in `SOURCE_ARCHIVES/`, that works too —
point me at it and I will use it instead.

Not urgent if item 1 arrives: with real game tiles, the mascots are only used
small, where they are already fine.

## Not requested — recorded so it is not generated by mistake

- **Nav bar icons.** The mockup uses flat single-colour glyphs (orange active,
  cocoa inactive), not illustrations. These are real widgets with a token
  colour. `clean_icons/home.png` is a glossy 3D cottage — **not** what the nav
  bar shows. Evidence: `_evidence/asset_gaps/mockup_navbar.png`.
- **Decor.** 22–147 px, which is fine for the footer meadow band — its only use.
- **Ghost pixels, untrimmed margins, icon size mismatch.** Phase 01's import
  pipeline fixes these. No new art needed.
- **Sounds.** 12 WAVs, re-generated from the legacy's `tool/generate_tones.dart`
  in Phase 05.
